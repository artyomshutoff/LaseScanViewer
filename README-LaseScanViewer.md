# LaseScanViewer 3.26.0

## Камера и слои в 3.26

При совмещении и расчёте сохраняются текущие поворот, масштаб, сдвиг и координатная рамка просмотра, включая повторный расчёт и автоматический расчёт после совмещения. Кнопка «Общий вид» / R по-прежнему сбрасывает камеру явно.

По умолчанию включена тёмная тема. Ранее явно сохранённый выбор темы в INI учитывается. Виртуальный тент отображается совместно с выбранными Full, Empty, грузом, фоном и водой; его объём показан отдельной строкой. Предыдущая версия 3.25 сохранена. Проверены применение тента в диалоге и неизменность камеры на реальных парах x64/x86. Математика расчёта не менялась.

## Интерфейс и виртуальный тент в 3.25

Верхнее меню убрано. Заголовок содержит [Version: 3.25.0] и меняет оформление вместе с темой. Все параметры доступны через кнопку «Настройки». Просмотр скана остаётся чёрным.

«Настройки → Слои просмотра → Виртуальный тент» показывает только выделенный груз выше горизонтального уровня бортов Empty: облако точек или объёмную поверхность. Тент можно включать вместе с любыми остальными слоями. Для показа только превышения отключите остальные слои вручную. Камера не меняется. Значение «Над бортами» — геометрический объём над плоскостью без провисания, а не общий объём груза. TotalVolume из SQ3 по-прежнему сравнивается с общим объёмом. При неопределённых бортах тент недоступен. Нулевой объём означает, что весь выделенный груз ниже бортов. Эта оценка зависит от качества Empty и уровня по воде.

Поиск ближайших точек при уточнении совмещения больше не выделяет память на каждый запрос. SSE2-ассемблер используется для дескрипторов на x64; экспериментальное ассемблерное ядро расстояния оказалось медленнее C++ и в EXE не включено. Проверки и измерения: PERFORMANCE-3.25-report.md.

## Совмещение и чёрный просмотр в 3.24

Окно 3D-просмотра всегда чёрное, независимо от темы панелей. Цвета скана, координат и надписей также сохраняются при переключении темы.

Для Full/Empty с совпадением ниже 45% добавлено уточнение по устойчивым крутым поверхностям кузова. Проверяются локальные плоскости, согласованность нормалей, пять стартовых сдвигов и двустороннее покрытие. Кандидат применяется только при улучшении геометрических показателей и распределённых опорах; иначе остаётся прежнее положение. Масштаб, наклон, количество глобальных гипотез и интегрирование объёма сохранены. После изменения XY высота заново уточняется по опорам.

На n-gk/13785 совпадение выросло 33.6% → 40.5%, RMS снизился 89.0 → 77.8 единиц файла. Отклонение итогового объёма от TotalVolume уменьшилось 3.07% → 1.68%; это не означает полного совпадения поверхностей. Предупреждение о ненадёжном/частичном совмещении сохранено. На шести дополнительных реальных парах положения и объёмы не изменились. Подробности и обе оценки объёма: ALIGNMENT-3.24-report.md и ALIGNMENT-3.24-results.csv. Предыдущая версия 3.23 сохранена.

## Интерфейс, отчёты и контрольная база в 3.23

Светлый интерфейс с зелёными акцентами, строгими панелями без верхнего меню «Файл / Вид / Настройки»; прежние инструменты просмотра сохранены. Тему выбирайте через «Настройки → Тема интерфейса → Светлая / Тёмная». В том же меню задаётся «Формат отчёта → HTML / PDF». Темы и формат сохраняются в LaseScanViewer.ini рядом с EXE, если папка доступна для записи; камера и результаты не меняются.

Кнопка «Загрузить базу SQ3» открывает TVM_Measurement_Data_Base.sq3. Загрузка доступна до открытия сканов; при выборе другого BIN сверка обновляется автоматически. Чтобы обновить данные после изменения базы, загрузите её заново. В настройках есть отключение базы. База открывается только для чтения. Ничего из неё не используется при совмещении или интегрировании объёма.

Совпадение проверяется по MeasurementID из BIN, а при отсутствии такого ключа — по единственной записи с IncomingMeasurementID/OutgoingMeasurementID. При наличии TruckID и метки BIN они должны совпадать. Неоднозначные записи, отсутствующие и отрицательные/нечисловые TotalVolume не считаются контрольными. Сверка использует именно TotalVolume, не CorrectedTotalVolume.

Справа внизу просмотра малым текстом показаны TotalVolume в м³ и разница со знаком: расчёт − TotalVolume. Процент = (расчёт − TotalVolume) / TotalVolume × 100%; при нулевом контроле процент не определён. Сравнивается итоговая оценка, показываемая приложением, в выбранном масштабе координат. До расчёта показывается только контроль и состояние. Отдельно обозначаются незавершённая запись, включённый в TotalVolume прицеп и ограничение расчёта выбранной областью.

Кнопка «Отчёт» сохраняет выбранный формат. Оба формата содержат изображение просмотра, параметры и сверку. PDF создаётся непосредственно приложением, без принтера или браузера: страницы A4 с переносом таблицы, кириллицей и сжатием без потерь. Страницы PDF растровые (около 150 dpi), текст в них не выделяется; HTML подходит для копирования текста. Сохранены портативные EXE x64/x86 и версия 3.22.

## CPU / GPU в 3.22

В «Настройки → Устройство вычислений» доступны CPU и GPU + CPU. По умолчанию выбран CPU. Выбор действует для следующего совмещения; текущие камера, слои и результат сохраняются. Для применения к уже совмещённой паре запустите «Совместить» заново. Настройка действует до закрытия программы.

В режиме GPU + CPU видеокарта ищет соответствия точек при переборе гипотез совмещения. Точное уточнение, проверки качества, интегрирование объёма и вода остаются на CPU. Это гибридный режим, а не перенос всего расчёта на видеокарту. Число гипотез и правила расчёта сохранены.

GPU используется через OpenCL из установленного драйвера, с двойной точностью и без приближённой арифметики. Программа автоматически выбирает поддерживаемую видеокарту; её название показано в настройках. Если подходящего устройства или драйвера нет, GPU недоступен, CPU работает. При ошибке GPU поиск продолжается на CPU. Дополнительные DLL с программой не требуются.

На GTX 1650 Ti проверены 5001 запрос поиска и три реальные пары: совмещение, объём и диапазон чувствительности CPU/GPU совпали точно. На этом компьютере гибридный режим оказался медленнее CPU; ускорение зависит от оборудования и данных. Подробнее: GPU-3.22-report.md. Версия 3.21 сохранена.

## Ускорение в 3.18

Независимые гипотезы совмещения распределяются между максимум четырьмя потоками; результаты собираются в прежнем порядке. Пространственные выборки и KD-деревья повторно используются при точном уточнении. Повороты в циклах используют заранее вычисленные sin/cos. В x64 расстояния между геометрическими признаками вычисляет встроенный ассемблер SSE2; на x86 действует C++-вариант. На текущем компьютере полный цикл чтения, совмещения и расчёта на трёх реальных парах стал быстрее в 1.84–2.04 раза (сокращение времени 46–51%). Это локальные замеры, а не гарантия для любого оборудования. Геометрия и совмещение совпадают; разница округления итогового объёма незначительна. Подробности в PERFORMANCE-3.18-report.md. ## Рамка и уровень воды в 3.17

Зона интереса показана пунктирной рамкой, цветными осями и подписями X, Y, Z с минимальным, средним и максимальным значениями в единицах файла. При выделенной области используются её границы; без выделения — область сравнения либо границы скана. Неограниченный диапазон Z заменяется измеренной высотой. Переключатель находится в «Настройки → Слои просмотра».

Обе заливки насыщенно-синие и непрозрачные. Для воды над грузом показана непрерывная плоскость уровня бортов по контуру Empty; замкнутые внутренние пропуски закрываются только в визуализации. Отверстия, открытые наружу, не закрываются. При скрытом грузе поверхность не имеет дыр на месте вершин насыпи; при включённом грузе его части выше воды остаются видимыми.

**Синяя плоскость обозначает уровень бортов, а не наличие воды внутри груза.** Число м³ свободного пространства, вместимость и объём груза рассчитываются прежними алгоритмами; визуальное закрытие пропусков не увеличивает их. Предыдущая версия сохранена.

## Слои и вода над грузом в 3.16

Откройте **Настройки → Слои просмотра**. Независимые переключатели: полный скан, Empty/Reference, объём груза, серые остальные точки, синяя вместимость пустого кузова, светло-синяя вода над грузом, значение объёма и сетка. Изменения видны сразу, камера и численный результат сохраняются. «Отмена» восстанавливает прежние слои. Виды можно сочетать или отключить все. Для груза и воды сначала выполните расчёт. **Настройки → Параметры расчёта** открывает прежние параметры.

Вода полного кузова означает оставшееся место над измеренной поверхностью Full до уровня перелива бортов Empty. Ячейки с грузом выше уровня бортов не добавляют воду; ячейки без Full исключены. Используется верхняя измеренная поверхность, чтобы не заполнять пространство внутри груза. Это оценка свободного пространства по имеющимся данным, не полный объём кузова и не новое измерение груза. Две заливки можно показывать отдельно. В м³ используется масштаб координат из настроек. PNG и HTML включают сравнение.

Алгоритмы совмещения и оценки объёма груза не изменены. Предыдущая версия сохранена.

## Заполнение по бортам в 3.12

После расчёта нажмите **«По бортам · вода»** слева. Синим показано горизонтальное заполнение пустого кузова до нижнего пути перелива через измеренные борта. Груз остаётся цветным. Показаны вместимость в м³, отношение объёма груза к вместимости и разница (вместимость минус груз). Значения более 100% возможны для груза с горкой. Кнопка повторно скрывает заливку; камера и результат расчёта груза сохраняются. PNG и HTML включают это сравнение.
Уровень определяется по совмещённому Empty/Reference, а не по вершине груза. Рёбра могут делить кузов на бассейны: объединяются поддержанные грузом области с близкими уровнями перелива. Короткие пропуски восстанавливаются только между измеренными поверхностями; большие остаются открытыми. Отсутствующие участки бортов/дна могут занижать оценку. При открытой стенке или недостатке опор функция сообщает, что замкнутые борта не найдены. Горизонталь задаётся осью Z; единицы берутся из настроек. Это оценка вместимости по скану, не независимое измерение.
Проверены 277 исправных реальных пар, закрытый кузов, пониженный борт, открытая стенка, малый пропуск, инвариантность к повороту/сдвигу и x64/x86. Изменений алгоритма объёма груза и обученной модели в 3.12 нет. Предыдущая 3.11 сохранена.


## Оценка объёма в 3.11

Нелинейная оценка использует 190 геометрических признаков совмещённых облаков. На 271 известной паре итоговое среднее отклонение от TotalVolume уменьшено с 1.035% до 0.555%, максимальное — с 9.648% до 4.482%. n-gk: 0.569%; dmu: 0.201%.

При оценке нет доступа к SQLite и сопоставления по ID/имени файла.

Проверены 277 исправных пар, совпадение независимых Python/C++ прогнозов на 271 паре, Empty/Empty, x64/x86 и GUI с экспортом. Пара 13955 повреждена. Подробности: CONTROL-3.11-report.md и CONTROL-3.11-results.csv. Предыдущие версии сохранены.

## Отделение кузова в 3.4.1

Фильтр действует при включённом отсечении бортов в настройках; его можно отключить.

## Быстрый старт

1. Откройте файл `*_Full.bin`. Если рядом есть `*_Empty.bin` с тем же номером, программа загрузит его автоматически и расставит роли. Иначе выберите оба файла или откройте Empty/Reference отдельно.
2. Нажмите **Рассчитать**. Программа выполнит расширенный поиск поворота и сдвига, выделит груз и проверит результат на пяти шагах сетки. Для повторного выравнивания уже загруженной пары нажмите **Совместить**. Совмещение и расчёт выполняются в фоне. Внизу отображаются прогресс-бар, этап и процент выполнения; процент не является оценкой оставшегося времени.
3. Нажмите **Сравнить** и проверьте совпадение неподвижных бортов: оранжевый — Full, голубой — Empty. При необходимости выделите кузов кнопкой **Область**, затем повторите расчёт.
4. **Точки / Поверхность** переключают изображение без изменения м³. **Отчёт** сохраняет автономный HTML; **PNG** — изображение; **Экспортировать PLY** — текущую геометрию.

ЛКМ — вращение; Shift+ЛКМ, ПКМ или средняя кнопка — перемещение. Колесо приближает к указателю. Двойной щелчок или R возвращает общий вид. Наведите мышь на кнопку для подсказки.

## Что означает результат

**Единица координат не подтверждена. По умолчанию предполагаются миллиметры.** Проверьте размер объекта и выберите единицы в настройках. Перевод мм³ в м³: деление на 1 000 000 000.

Расчёт является оценкой 2.5D **в измеренной и ограниченно восстановленной общей области**, а не сертифицированным полным объёмом. Для каждой общей XY-ячейки берётся разность высот Full и Empty, положительная разность умножается на площадь. По умолчанию высота — нижний 10%-квантиль с интерполяцией; при числе точек меньше 10 используется медиана. Этот режим уменьшает влияние смешанных точек дна и стенки и проверен по n-gk. Медиана и остальные режимы доступны в настройках. Заданный шаг — 100 исходных единиц. По умолчанию для плотных сканов автоматически используется 75, а при заметном вкладе пропусков — 125. Автоматический шаг отключается в настройках; фактический шаг показан под моделью и в отчёте.

Короткие и небольшие замкнутые пропуски могут восстанавливаться; открытые разрывы, большие пробелы и ячейки без данных в обоих сканах не заполняются. Показатель «Общая сетка» — доля измеренных и восстановленных общих ячеек в охватывающем прямоугольнике, а не процент достоверности. Стенка, выброс или неправильное совмещение способны менять объём.

«При разных шагах» — минимум и максимум оценок при 0,5× / 0,75× / 1× / 1,25× / 1,5× выбранного шага с теми же фильтрами, а также при трёх смещениях начала сетки для автоматической области. **Это проверка чувствительности, не доверительный интервал и не измеренная погрешность.** При сильной зависимости результат помечается предварительным.

## Что изменилось в 3.4

- Плотные поверхности рассчитываются на более мелком шаге; при восстановленном вкладе больше 1% автоматически применяется более крупный шаг. Правило зависит от геометрии сканов, контрольные значения в EXE не используются.
- Ячейки со смесью дна и стенки уточняются по соседям. Однородные поверхности и измеренные тонкие рёбра не сглаживаются.
- Восстанавливаются небольшие замкнутые пропуски по фиксированной границе, до 600 итераций с ранней остановкой. Их вклад учитывается отдельно. В облаке точек остаются реальные измерения; восстановленный объём виден в режиме «Поверхность».
- Проверяются пять разрешений и три смещения сетки. Ход вычислений показан в прогресс-баре. Искусственных задержек нет.
- «Автоматически выбирать шаг» и восстановление пропусков можно отключить в настройках.

Результаты нового полного прогона 89 пар: **NGK-3.4-report.md**, таблица **NGK-3.4-results.csv**. Все эти данные использовались при доработке 3.4, поэтому это проверка на известном наборе, а не независимая оценка точности. Прежнее разделение 62/27 ниже относится только к истории версии 3.3. Предыдущие EXE, включая v1 и 3.3, сохранены в releases.

## Расчёт объёма в 3.2

- Резкий перепад поверхности Empty сам по себе больше не исключает груз: внутренние рёбра и наклонный пол не должны разрезать насыпь. Для подавления небольшого остатка на борте требуется сходный крутой перепад в обоих сканах и ΔZ не больше двойного порога. Фильтр также удаляет одиночные точки и узкие полосы, используя соседнюю поддержку.
- Включено ограниченное восстановление пропусков. Для ячейки без наблюдения в одном скане ищутся исходные измерения по противоположным направлениям; минимум две неколлинеарные пары должны согласоваться в пределах половины шага по высоте. Длина пары — не больше четырёх шагов сетки (по диагонали геометрическая длина больше), поиск — максимум три ячейки в сторону. Большой наклон и несогласованные перепады отвергаются. Восстановленные значения не используются для повторного заполнения; отсутствующие в обоих сканах ячейки не добавляются.
- Переключатель **Восстанавливать короткие пропуски между измерениями** находится в настройках. Вклад восстановленных ячеек показан отдельно под моделью и в HTML. Если вклад больше 10%, результат помечается предварительным. Этот процент — порог проверки, а не точность измерения.
- Облако груза содержит только реальные точки Full. Поверхность дополнительно показывает рассчитанные ячейки; их объём учтён в итоговом числе. Новые лазерные точки не выдумываются.
- Основной результат считается на выбранном шаге. Четыре дополнительных расчёта оценивают чувствительность; максимум диапазона не подставляется вместо результата. Прогресс отражает завершённые этапы, а не оставшееся время.

В Learn 6109 устранено ошибочное исключение поперечной полосы груза. По умолчанию (крупнейшая область) получается около 24,80 м³, при всех областях — около 24,90 м³; прежний результат всех областей составлял 20,33 м³. Около 0,13 м³ относится к восстановленным ячейкам. Все числа предполагают мм и не подтверждены контрольным объёмом.

## Расширенное совмещение в 3.1

- 144 начальных варианта по всему кругу 0–360°: шаг 15°, две начальные высоты и разные доли совпадающей поверхности (30% / 60%). Дополнительно проверяются 11 углов рядом с лучшим вариантом.
- Отдельные проходы используют верхнюю полосу скана. Это помогает найти верхние части кузова, когда дно Empty закрыто грузом в Full. Полоса — геометрическая гипотеза, а не гарантированная классификация бортов; все варианты оцениваются на общем облаке.
- Начальный центр по X/Y берётся по квантилям 2–98%, уменьшая влияние отдельных удалённых точек. Поворот 180° проверяется явно, но не навязывается файлам по имени.
- До восьми различных вариантов проходят точное уточнение на трёх разрешениях. Похожие по качеству противоположные ориентации считаются неоднозначными: расчёт выполняется с отметкой «Предварительно».

В паре Learn 6066 новый алгоритм находит около −179,14° вместо прежних +2,27°. Подробная проверка всех пар — в отчёте Learn. Это исправление совмещения, а не независимое подтверждение объёма в м³.

## Изменения алгоритма по Learn

- Поддержаны записи точек длиной 52 и 60 байт, в том числе смешанные в одном файле. Сохраняется строгая проверка структуры, служебные координаты не добавляются к точкам.
- Удалено ошибочное правило «нижние 20% высот всегда дорога» из отделения груза. В Learn эта часть часто является дном кузова.
- Глобальный поиск поворота вокруг Z проверяет два начальных положения по высоте: по нижней границе и по верхнему квантилю. Это учитывает ситуацию, когда груз закрывает нижнюю часть пустого скана.
- При выравнивании крайние высоты оцениваются по квантилям, чтобы отдельная низкая точка не смещала весь подбор. После глобального поиска выполняется устойчивое уточнение на нескольких разрешениях с взаимными соответствиями и весами по остаткам.
- Для настоящей пары Full/Empty дополнительный критерий штрафует большие области, где Full ниже Empty. Больший положительный объём сам по себе не улучшает оценку совмещения. Для Reference применяется геометрическое совмещение без этого критерия.
- При частичном перекрытии проверяется распределение опорных соответствий по двум осям. Неоднозначные и слабые решения не принимаются автоматически. Ручное подтверждение не является доказательством правильности.
- Для отделения груза используются порог положительной разности, поддержка соседних ячеек и связные области. Размер окрестности зависит от размера скана и шага сетки. В отличие от прежней версии низкая поверхность не удаляется просто из-за её высоты.

Фильтр бортов может убрать узкий настоящий груз. Его можно отключить в настройках и сравнить результат. Порог ΔZ исключает ячейку целиком, но не вычитается из высоты оставленных ячеек. За пределами ограниченного восстановления неизмеренные части груза не дорисовываются.

## Серое окружение груза

После расчёта нажмите **Остальные точки** слева. Выделенный груз сохраняет высотные цвета, остальные точки исходного Full показываются серыми (в том числе вне области расчёта). Повторное нажатие скрывает окружение. Режим работает для облака и поверхности; серые точки не меняют объём и не добавляются к PLY груза. PNG и HTML-отчёт сохраняют изображение с окружением. Переключение сохраняет текущие ракурс, масштаб и положение модели. Для показа всего окружения нажмите «Общий вид» или R.

Прогон объёма без повторного поиска совмещения: `tests/volume_benchmark.cpp` читает сохранённые параметры из `build/learn-audit-3.1.csv`, рассчитывает пять разрешений для 69 пар и записывает `build/volume-audit-3.2.csv`. CSV сохраняет оценку надёжности совмещения независимо от разрешения расчёта объёма.

## Расчёт при ненадёжном совмещении в 3.2.1

Кнопка «Рассчитать» использует найденный поворот и сдвиг даже при низком или неоднозначном совпадении. При первом запуске расчёт автоматически продолжается после совмещения; повторное нажатие не запускает поиск заново. Объём и HTML отмечаются как предварительные, исходная оценка надёжности сохраняется. При смене пары нужен новый поиск. Ошибки чтения, отсутствие общих ячеек и недопустимые параметры по-прежнему обрабатываются как ошибки. Отчёты аудита 3.1/3.2 описывают поведение прежних версий.
